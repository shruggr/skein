Skein Architecture Map

The host process, the instance's surface, the kernel's modules, and the path one request takes. Drawn from docs/ARCH.md, docs/VM.md, docs/MESSAGES.md and the source as of 2026-10-04 (main). File paths are in the shruggr/skein repo unless named otherwise.

1. The host process

One node process, skein-host run, is transports + providers + store + oracle. It verifies nothing and routes nothing. Each instance is a kernel process over its own SQLite file; the host skein is one of them, the only one whose address book names the instance manager.

ComponentFileDoes
HTTP routersrc/host/router.tsPicks the instance by origin or /@handle, appends the request as an entry, holds the socket until the thread rests, returns the answer. Serves discovery on its own origin.
libp2p nodesrc/host/p2p.tsOne node per instance that declares libp2p; topic messages and stream frames appended as requests; follows the dispatch table live.
Providerssrc/host/providers.tsfetch, waker, cron, libp2p, status, manager. Recipients of emit. Each answers with a signed message appended as a local request.
Instance managersrc/host/instances.tsReads host.db's instances on start and boots each kernel; creates, starts, stops instances on messages from the host skein only.
Broadcastersrc/host/arc.tsOne Arcade per host. Broadcast events queued durably; statuses back by SSE and webhook, delivered to every instance holding the transaction.
Feedssrc/host/feeds.tsSSE consumer with Last-Event-ID. Headers become events in box chain for instances whose table takes them.
Oraclesrc/host/oracle.tsOne master secret; each instance's root key is a BRC-42 child keyed by handle. Answers the kernel's wallet frame.
Kernel processsrc/host/kernel.tsskein-kernel serve per instance; length-prefixed dag-cbor frames on stdio; started on demand.
Storesrc/runtime/sqlite.tsOne runtime.db per instance. blocks and entries are the record; chains, updates, edges are indexes rebuilt from blocks.
host.dbsrc/host/instances.tsinstances, fuel_ledger, stream_cursor, status_seen, broadcast_queue, cron_schedule, host_settings. Not derived from any log.

2. The instance's surface

The kernel's whole surface is five frames. In: admit, answer, call. Out: wallet, emit. Every transport reduces to admit; every read that is not a request is a call; everything that leaves is an emit routed by the address book.

FrameDirectionMeaning
admitinAppend an entry and run the steps it drives. HTTP, libp2p, local provider answers, events and browser mail all arrive this way.
answerinWait until a request's thread comes to rest; the resting state is the HTTP response. Past two minutes, 503 + Retry-After.
callinRun a program function over current state. No entry, no writes, not replayed. The explorer's reads; a route's thread answers read and the host then calls.
walletoutA signing request to the oracle. The one recorded syscall: request and answer are written on the step and replay serves them from there.
emitoutWhat a committed step sent: a signed message to a key in the address book, or a broadcast event. The host delivers it after commit.

3. Kernel modules

The kernel is a WASI machine in Zig. Programs see only its import table; the four tables and the log sit beneath the scheduler; the engine runs modules on wasmtime (native) or V8 (browser). It has no disk, network, clock or process table.

ModuleRole
scheduler.zigConsumes the log in order, one entry and one step at a time. Routes a message by (sender, box) through the dispatch table, an event by box, a reply to the thread awaiting it.
dispatch.zigFolds the dispatch chain into rows; first match wins; a row with program kernel is an admin operation (objects, head, dispatch, peers, claim).
heads.zigNamed chains: origin {kind: head, name}, one update per move {tree, thread, input, at}. Write scope by name: an app advances only <app>/….
objects.zig / store.zigBlocks by CID. Reads are global: holding a CID is the permission. Native backing is SQLite, browser is IndexedDB.
log.zigEntry shapes (format 8). Entries are unsigned; the sender signed its request, prev fixes order, time is the host's stamp.
envelope.zigMail records and their ids; the unique map so a record is admitted once.
runner.zig / engine*.zigOne step of one program: fuel on, imports bound, writes collected and committed only when the step ends without error.
wasi.zig / vfs.zig / syscalls.zigThe WASI host inside the kernel. Pure syscalls are answered deterministically and never recorded.
oracle.zigThe wallet import: the one recorded call. Replay serves the recorded answer.
replay.zigRe-executes the log; recovery after a crash re-runs a step that was cut off.
index.zigOne Merkle search tree per query, one state record holding every root.
ipc.zig / serve.zigThe five frames over stdio to the host process.

4. One HTTP request, end to end

A BRC-104 signed call to an app function, with an emit to a provider on the way. Time runs left to right; each column is a component from the diagrams above.

  1. The client signs the request on its BRC-104 session and sends it to the instance's origin.
  2. The router picks the instance by URL and appends the raw request as entry n. It holds the socket.
  3. The scheduler steps the front door on the entry. It verifies the signature against the session record under frontdoor/sessions.
  4. The dispatch table matches (http, path, sender), first row wins, and the program is launched as the request's thread.
  5. The step reads any CID it holds, writes records, advances heads under its own name, and asks the oracle to sign. The signing is the one recorded call.
  6. The step ends; its writes commit; its emits leave. The thread rests, and the resting state is the HTTP answer.
  7. A provider's answer arrives later as a local entry whose replyTo names the emitted record, and the scheduler steps the thread again.
